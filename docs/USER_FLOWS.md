# Information Architecture and User Flows

## Main navigation

1. Dashboard
2. Inbox
3. Projects
4. Next Actions
5. Areas
6. Incubator
7. Reviews
8. Search
9. Settings

## Brain dump to structured object

1. User opens Quick Capture.
2. User writes or dictates an unstructured thought.
3. The input is saved immediately in the Inbox.
4. AI analyses the input.
5. AI proposes type, area, project, priority and next action.
6. User approves or edits the proposal.
7. The item is converted into the selected object.
8. The original input remains traceable.

## Idea to incubator

1. User captures a new product idea.
2. AI identifies that it is not immediately actionable.
3. AI recommends the Incubator.
4. User confirms.
5. The idea receives an area, potential score and future review date.
6. The idea remains inactive until promoted.

## Idea to active project

1. User opens an incubated idea.
2. User selects Promote to Project.
3. The system requests a defined outcome.
4. AI proposes milestones and a first next action.
5. The system checks the active project limit.
6. User pauses another project or confirms an exception.
7. The project becomes active.

## Daily execution

1. User opens the Dashboard.
2. The system presents daily focus and available next actions.
3. User filters by energy, duration or context.
4. User starts one action.
5. User completes, postpones or blocks it.
6. The related project is updated.
7. If no next action remains, AI proposes one.

## Weekly review

1. The system reminds the user to perform a review.
2. Inbox items are processed.
3. Overdue and blocked actions are examined.
4. Projects without progress are identified.
5. AI highlights conflicts and overload.
6. User chooses what to continue, pause, delegate or remove.
7. User selects three outcomes for the following week.
8. The review is saved historically.

## Contextual AI request

1. User opens the AI Assistant from a project or area.
2. The assistant receives the relevant context.
3. User requests analysis or planning.
4. The assistant responds using structured project data.
5. Suggested changes are shown as proposals.
6. User accepts or rejects each change.
7. Accepted changes update the system.

## UX rules

- Save captured input before processing it.
- Never hide AI changes.
- Every project must display one clear next action.
- Avoid exposing the full graph unless requested.
- Use progressive disclosure for complex details.
- Keep the default view calm and focused.
- Make destructive actions reversible where possible.
