# Product Roadmap

## Phase 0 — Documentation and alignment

Goal: establish one shared product definition before further development.

Deliverables:

- product vision;
- functional specification;
- user flows;
- architecture;
- data model;
- development roadmap;
- strategic changelog.

Exit condition: the application can be evaluated against a written source of truth.

## Phase 1 — Functional MVP

Goal: provide a reliable manual personal operating system.

Scope:

- authentication;
- dashboard;
- quick capture;
- inbox;
- areas;
- projects;
- tasks;
- incubator;
- basic weekly review;
- search;
- responsive design.

AI may initially be mocked or limited.

Exit condition: a user can capture, organise, prioritise and execute work without relying on external tools.

## Phase 2 — AI classification layer

Goal: automate the transformation from natural language to structured objects.

Scope:

- input classification;
- summaries;
- area and project association;
- next-action generation;
- confidence scores;
- reviewable AI proposals.

Exit condition: most Inbox items can be processed with minimal manual editing.

## Phase 3 — Context and memory

Goal: make AI responses aware of persistent user context.

Scope:

- semantic search;
- embeddings;
- duplicate detection;
- contextual project assistant;
- relationship suggestions;
- decision history.

## Phase 4 — Review and decision intelligence

Goal: support strategic prioritisation.

Scope:

- weekly review automation;
- overload detection;
- conflicting-priority detection;
- stalled-project detection;
- time-budget analysis;
- explainable recommendations.

## Phase 5 — Integrations and automation

Potential integrations:

- Google Calendar;
- Gmail;
- GitHub;
- Google Drive;
- ClickUp;
- Notion;
- Slack;
- voice transcription.

## Phase 6 — Productisation

Scope:

- onboarding;
- configurable templates;
- subscriptions;
- multi-device experience;
- analytics;
- privacy and export;
- user research;
- team or coach access.

## Current priorities

1. Synchronise and inspect the complete source code.
2. Compare implemented screens and features with the specification.
3. Mark functionality as implemented, partial or missing.
4. Stabilise the capture-to-action loop.
5. Avoid advanced integrations until the MVP is reliable.
